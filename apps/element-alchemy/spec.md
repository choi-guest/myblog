# 원소 연금술 (Element Alchemy) 계획서

## 1. 게임 소개

연금술사의 작업대(5×5 판) 위에 물·불·흙·바람 네 원소 타일이 하나씩 떨어진다. 판 전체를 한 방향으로 밀면 타일이 미끄러지고, 부딪친 두 타일이 **같은 원소면 등급이 오르고**, **정해진 짝의 다른 원소면 새 원소로 변성**한다. 물과 불이 만나면 증기, 불과 흙이 만나면 용암이 되는 식이다.

목표는 숫자를 키우는 것이 아니라 **조합 도감을 채우는 것**이다. 기본 원소에서 화합물, 화합물에서 희귀 원소를 거쳐 최종 원소 "현자의 돌"을 만들면 승리하며, 그 뒤에도 판이 막힐 때까지 계속해 점수를 올릴 수 있다. 다음에 나올 원소를 미리 보여 주므로, 어떤 원소를 어디에 모아 둘지 계획하는 것이 핵심 전략이다.

### 2048과의 차별점 (구현 시 반드시 지킬 것)

| 항목 | 2048 | 원소 연금술 |
| --- | --- | --- |
| 판 | 4×4 | **5×5** |
| 타일 | 2의 거듭제곱 숫자 | 원소 + 등급(Ⅰ~Ⅴ), 숫자 표기 없음 |
| 생성 | 매 턴 2 또는 4 무작위 | 매 턴 기본 원소 1개(10턴마다 2개), **다음 원소 미리보기** |
| 합치기 | 같은 숫자만 | 같은 원소(등급 상승) + **다른 원소 조합(변성)** |
| 목표 | 2048 타일 | **현자의 돌** 제작 / 도감 완성 |
| 최대치 | 없음(계속 커짐) | 등급 Ⅴ에서 한 번 더 합치면 **승화**(타일 소멸 + 보너스) |
| 디자인 | 베이지·주황 숫자 타일 | 원소별 고유 색, 원소 이름·기호 표기, 짙은 작업대 느낌 |

문구 "2048", "Join the numbers" 등 2048의 문구·색상(#edc22e, #f2b179 계열 등)·레이아웃을 사용하지 않는다.

## 2. 상세 규칙

### 2.1 판

- 5×5 격자(25칸). 좌표는 `(row, col)`, 0부터 시작, 왼쪽 위가 `(0,0)`.
- 칸에는 타일이 0개 또는 1개.

### 2.2 타일

타일은 `{ id, element, grade }` 로 표현한다.

- `element`: 원소 키(아래 표)
- `grade`: 1~5 (화면에는 Ⅰ~Ⅴ 로마 숫자 또는 점 개수로 표시)
- `id`: 애니메이션 추적용 고유 번호

### 2.3 원소 목록 (총 15종)

| 단계 | 키 | 이름 | 기호 | 만드는 법 |
| --- | --- | --- | --- | --- |
| 기본 | `water` | 물 | 水 | 생성 |
| 기본 | `fire` | 불 | 火 | 생성 |
| 기본 | `earth` | 흙 | 土 | 생성 |
| 기본 | `wind` | 바람 | 風 | 생성 |
| 화합물 | `steam` | 증기 | 蒸 | 물 + 불 |
| 화합물 | `lava` | 용암 | 熔 | 불 + 흙 |
| 화합물 | `mud` | 진흙 | 泥 | 흙 + 물 |
| 화합물 | `lightning` | 번개 | 雷 | 바람 + 불 |
| 화합물 | `rain` | 비 | 雨 | 바람 + 물 |
| 화합물 | `sand` | 모래 | 砂 | 바람 + 흙 |
| 희귀 | `life` | 생명 | 生 | 진흙 + 번개 |
| 희귀 | `glass` | 유리 | 璃 | 모래 + 용암 |
| 희귀 | `storm` | 폭풍 | 嵐 | 비 + 번개 |
| 희귀 | `obsidian` | 흑요석 | 曜 | 용암 + 비 |
| 최종 | `stone` | 현자의 돌 | 賢 | 생명 + 유리 |

- 조합은 순서와 무관하다(물+불 = 불+물).
- 표에 없는 짝(예: 물+흙은 진흙이지만, 물+용암은 없음)은 **아무 일도 일어나지 않고** 서로 막힌다.
- 도감 대상은 기본 원소를 제외한 **11종**(화합물 6 + 희귀 4 + 최종 1).

### 2.4 두 타일이 만날 때 (판정 함수 `react(a, b)`)

이동 방향 앞쪽 타일을 `a`, 뒤에서 미끄러져 온 타일을 `b`라 한다. 다음 순서로 판정한다.

1. **같은 원소, 같은 등급, 등급 < 5** → **강화**: `{ element, grade: grade + 1 }` 하나가 된다.
2. **같은 원소, 둘 다 등급 5** → **승화**: 두 타일 모두 사라진다(칸이 빈다).
3. **다른 원소, 조합표에 있음, 두 등급이 같음** → **변성**: `{ element: 결과, grade: 같은 등급 }` 하나가 된다.
4. 그 밖(등급이 다르거나, 조합표에 없음) → 반응 없음. `b`는 `a` 뒤에 멈춘다.

즉 **반응은 항상 같은 등급끼리만** 일어난다. 등급을 맞추는 것이 전략의 요소다.

### 2.5 이동과 합치기 순서

한 번의 입력(상·하·좌·우) = 한 턴. 각 줄(행 또는 열)을 독립적으로 처리한다.

1. 이동 방향 쪽 끝 칸부터 반대쪽으로 타일을 순서대로 꺼낸다(빈칸 제외).
2. 결과 줄을 앞에서부터 채운다. 새 타일 `b`를 놓을 때 결과 줄의 마지막 타일 `a`가 **이번 턴에 반응으로 만들어진 타일이 아니면** `react(a, b)`를 시도한다.
   - 강화·변성: `a` 자리를 결과 타일로 바꾸고 "이번 턴 반응됨" 표시.
   - 승화: `a`를 결과 줄에서 제거하고 `b`도 버린다. 다음 타일은 그 빈자리로 당겨지며, 결과 줄의 새 마지막 타일(반응되지 않은 타일이라면)과 다시 반응을 시도할 수 있다.
   - 반응 없음: `b`를 `a` 뒤에 둔다.
3. **한 타일은 한 턴에 최대 한 번만 반응한다.** 반응 결과 타일은 그 턴에 다시 반응하지 않는다. (예: 물Ⅰ·물Ⅰ·불Ⅱ를 왼쪽으로 밀면 물Ⅱ가 되고, 불Ⅱ는 그 뒤에 멈춘다. 다음 턴에 물Ⅱ+불Ⅱ=증기Ⅱ 가능.)
4. 판의 어떤 타일도 움직이거나 반응하지 않았다면 **턴으로 치지 않는다**(턴 수 증가·생성·점수 없음).

### 2.6 타일 생성

- **시작**: 서로 다른 기본 원소 3개를 등급 Ⅰ로 무작위 빈칸에 놓는다. "다음 원소" 큐 2개를 채운다.
- **매 유효 턴 후**: 큐 맨 앞 원소를 등급 Ⅰ로 무작위 빈칸 1곳에 놓고, 큐 끝에 새 원소를 추가한다.
- **10턴마다**(턴 수가 10의 배수가 된 직후): 1개를 추가로 더 생성한다(큐에서 하나 더 꺼냄). 빈칸이 부족하면 놓을 수 있는 만큼만.
- **원소 뽑기**: 4원소를 같은 확률로 뽑되, **같은 원소가 3번 연속 나오지 않게** 한다(직전 2개가 같으면 그 원소를 제외하고 뽑기).
- 난수 함수는 `game.js`에 주입할 수 있게 해(`createGame({ rng })`) 테스트에서 고정 시드를 쓸 수 있도록 한다.

### 2.7 승리와 게임 오버

- **승리**: 현자의 돌을 처음 만들면 "대업 달성" 안내를 띄운다. [계속하기]로 이어서 하거나 [새 게임]을 고를 수 있다. 승리는 게임을 끝내지 않는다.
- **게임 오버**: 생성까지 끝난 뒤 판이 가득 차 있고, 네 방향 어느 쪽으로도 이동/반응이 불가능하면 종료. (판정: 각 방향에 대해 이동 시뮬레이션을 돌려 변화가 있는지 확인.)
- 게임 오버 화면에 최종 점수, 턴 수, 도감 달성 수(n/11), 최고 점수 갱신 여부를 보여 준다.

## 3. 점수 규칙

| 사건 | 점수 |
| --- | --- |
| 강화 (새 등급 g) | `5 × g²` → Ⅱ 20, Ⅲ 45, Ⅳ 80, Ⅴ 125 |
| 변성 (화합물, 등급 g) | `30 × g` |
| 변성 (희귀, 등급 g) | `80 × g` |
| 변성 (현자의 돌, 등급 g) | `300 × g` |
| 승화 (등급 Ⅴ 두 개 소멸) | 기본 원소 200 / 화합물 400 / 희귀 800 / 현자의 돌 2000 |
| 첫 발견 (이번 게임에서 도감에 처음 등록) | 화합물 +50, 희귀 +150, 현자의 돌 +500 |
| 도감 보너스: 화합물 6종 모두 발견 | +300 (1회) |
| 도감 보너스: 희귀 4종 모두 발견 | +800 (1회) |
| 도감 보너스: 11종 전부 발견 | +2000 (1회) |

- **연쇄 배율**: 한 턴에 반응이 n번(n ≥ 2) 일어나면 그 턴의 반응 점수(강화·변성·승화) 합에 `1 + 0.25 × (n − 1)`을 곱하고 반올림한다. 첫 발견·도감 보너스에는 배율을 적용하지 않는다.
- 도감은 **게임마다 새로 시작**한다(보너스도 게임당 1회).
- 최고 점수는 `localStorage` 키 `element-alchemy:best`에 저장. 읽기/쓰기 모두 `try/catch`, 실패하면 0으로 보고 게임은 정상 진행.
- 점수 계산은 `game.js`의 순수 함수에서 하고, 턴 결과로 `{ moved, events: [{ type, element, grade, points }], gained, won, over }`를 돌려준다.

## 4. 화면 구성

모바일 우선 한 열 레이아웃. 넓은 화면(`min-width: 900px`, Review 1차 문제 7 반영)에서는 판 왼쪽, 도감 오른쪽 두 열.

1. **헤더**: 제목 "원소 연금술", [새 게임] 버튼, [블로그로] 링크(`../../index.html`, 블로그 파일에 의존하지 않는 단순 링크).
2. **점수판**: 점수 / 최고 점수 / 턴 수 세 칸. 점수가 오르면 "+n" 표시(감속 모드에서는 애니메이션 없이 표시만).
3. **다음 원소**: 큐 2개를 작은 타일로 표시("다음", "그다음").
4. **게임판**: 정사각형 5×5, 폭 `min(100vw − 32px, 480px)`. 타일에는 기호(큰 글자) + 이름(작은 글자) + 등급(Ⅰ~Ⅴ)을 표시해 **색만으로 구분하지 않는다**. 등급이 높을수록 테두리 두께/채도가 올라간다.
5. **도감**: 11칸 격자. 미발견 칸은 결과 이름을 "?"로 가리고, 재료 힌트(예: "물 + 불")는 처음부터 공개한다. 발견하면 원소 이름과 색이 드러난다. 달성 수 `n/11` 표시.
6. **조작 안내**: "방향키·WASD 또는 스와이프로 밀기" 한 줄 + 화면 방향 버튼 4개(▲▼◀▶, 각 44×44px 이상, 판 아래).
7. **게임 오버 / 승리 대화상자**: `<dialog>` 요소. 결과 요약과 [다시 하기](게임 오버) 또는 [계속하기]/[새 게임](승리). 열리면 주 버튼에 포커스, Esc로 닫기(게임 오버에서는 닫아도 판은 멈춘 상태로 [새 게임]만 가능).

### 디자인

- 색상은 모두 `:root` CSS 변수. 원소별 `--el-water`, `--el-fire` 등 15개 + 배경/텍스트/테두리 변수.
- 라이트: 밝은 양피지 계열 배경, 다크: 짙은 남색 작업대. `prefers-color-scheme`으로 전환(수동 토글은 필수 아님, 넣는다면 `data-theme` + `localStorage` try/catch).
- 타일 글자와 배경의 대비 4.5:1 이상(라이트/다크 각각 확인). 기호처럼 큰 글자도 같은 기준을 지킨다.
- 그림자·그라데이션 최소화. 폰트는 시스템 폰트 스택(CLAUDE.md 참조).
- 애니메이션: 이동 120ms, 반응 시 짧은 확대. `prefers-reduced-motion: reduce`이면 transition/animation 없음.

## 5. 조작

- **키보드**: 방향키, `W A S D`(대소문자 무관). 게임판이나 문서에 포커스가 있을 때 동작하고, 방향키 기본 스크롤은 `preventDefault`로 막는다(단, 대화상자가 열려 있거나 입력이 버튼 포커스일 때 Enter/Space는 방해하지 않음). 새 게임은 실수 방지를 위해 단축키 없이 [새 게임] 버튼으로만 시작한다.
- **스와이프**: 게임판에서 `pointerdown` → `pointerup` 이동 거리 30px 이상, 큰 축 방향으로 판정. 게임판에 `touch-action: none`을 줘 스와이프 중 페이지가 스크롤되지 않게 한다(판 밖은 정상 스크롤).
- **화면 버튼**: ▲▼◀▶ 버튼으로도 이동 가능(키보드·스와이프가 어려운 사용자용).
- **입력 잠금**: 애니메이션 중 들어온 입력은 1개까지 버퍼링 후 처리(감속 모드에서는 즉시 처리).
- **접근성**:
  - `aria-live="polite"` 상태 영역에 턴 결과를 문장으로 알림. 예: "왼쪽으로 밀었습니다. 물 Ⅱ 강화, 증기 Ⅰ 발견! +130점. 다음 원소: 흙."
  - 이동이 없으면 "그 방향으로는 움직일 수 없습니다."
  - 게임판은 `role="grid"`, 각 칸 `role="gridcell"`에 `aria-label`("3행 2열, 불 등급 2" / "빈칸").
  - 방향 버튼에 `aria-label`("위로 밀기" 등), 모든 버튼에 `:focus-visible` 스타일.
  - 승리/게임 오버는 `<dialog>`로 포커스 이동.

## 6. 파일 구조

`apps/element-alchemy/` 안에서 자체 완결. 외부 CDN·라이브러리 없음, 빌드 도구 없음.

```
apps/element-alchemy/
├── index.html        # 게임 페이지 (lang="ko", charset, viewport, FOUC 방지 테마 인라인 스크립트(토글을 넣을 경우))
├── style.css         # 테마 변수, 레이아웃, 타일·도감·대화상자 스타일, reduced-motion
├── js/
│   ├── elements.js   # 원소 데이터(키·이름·기호·단계), 조합표, 점수 상수 — 순수 데이터
│   ├── game.js       # 게임 상태와 규칙: createGame, move(dir), react, 생성, 점수, 게임오버 판정 — DOM 접근 금지
│   ├── render.js     # 상태 → DOM 그리기 (판, 점수판, 큐, 도감, 대화상자), aria-live 문장 생성
│   ├── input.js      # 키보드·스와이프·화면 버튼 → 방향 이벤트
│   ├── storage.js    # 최고 점수 읽기/쓰기 (try/catch)
│   └── main.js       # 진입점: 모듈 연결, 새 게임/계속하기 처리
├── preview.svg       # 블로그 카드용 미리보기 이미지 (판 일부 + 원소 타일 몇 개)
├── plan-brief.md     # (기존) Plan 지침
└── spec.md           # 이 문서
```

- ES 모듈, `const`/`let`, 세미콜론, 2칸 들여쓰기.
- `innerHTML` 사용 금지(고정 문자열 포함, `textContent`와 `el()` 식 요소 생성으로 그린다).

## 8. 검증 기준 (Review 체크리스트)

### 규칙
- [ ] 판이 5×5이고 시작 타일 3개가 서로 다른 기본 원소 등급 Ⅰ이다.
- [ ] 같은 원소·같은 등급 → 등급 +1, 등급 Ⅴ 두 개 → 승화(둘 다 소멸).
- [ ] 조합표 6+4+1개가 모두 동작하고, 순서를 바꿔도 같은 결과다.
- [ ] 등급이 다르거나 조합표에 없는 짝은 반응하지 않는다.
- [ ] 한 타일은 한 턴에 한 번만 반응한다(예: 물Ⅰ 물Ⅰ 물Ⅰ 물Ⅰ 왼쪽 → 물Ⅱ 물Ⅱ, 물Ⅲ 아님).
- [ ] 변화 없는 입력은 턴·생성·점수를 바꾸지 않는다.
- [ ] 매 턴 1개, 10의 배수 턴에 1개 추가 생성. 미리보기 큐와 실제 생성 원소가 일치한다.
- [ ] 같은 원소가 3번 연속 생성되지 않는다.
- [ ] 현자의 돌 첫 제작 시 승리 대화상자, [계속하기] 후 정상 진행.
- [ ] 판이 가득 차고 네 방향 모두 불가할 때만 게임 오버.

### 점수
- [ ] 강화·변성·승화 점수가 표대로 계산된다.
- [ ] 연쇄 배율이 반응 점수에만 적용되고 반올림된다.
- [ ] 첫 발견·도감 보너스가 게임당 1회만 지급된다.
- [ ] 최고 점수가 새로고침 후에도 유지되고, `localStorage`를 막아도 오류 없이 동작한다.

### 화면·조작
- [ ] 방향키, WASD, 스와이프, 화면 버튼 모두 동작. 방향키로 페이지가 스크롤되지 않는다.
- [ ] 375px 폭에서 가로 스크롤 없음, 판이 화면 안에 들어오고 좌우 여백 16px 이상.
- [ ] 버튼·방향 버튼 터치 영역 44×44px 이상.
- [ ] 라이트/다크 모두 텍스트·타일 글자 대비 4.5:1 이상, 타일이 색 외에 기호·이름·등급으로 구분된다.
- [ ] `prefers-reduced-motion: reduce`에서 애니메이션이 없다.
- [ ] 스크린 리더 상태 알림(aria-live)이 턴마다 갱신되고, 대화상자 열릴 때 포커스가 이동한다.
- [ ] `<html lang="ko">`, `<meta charset="utf-8">`, viewport 메타 포함.

### 독창성·구조
- [ ] 2048의 판 크기·숫자 타일·색상·문구를 쓰지 않는다.
- [ ] 외부 라이브러리·CDN·`package.json` 없음, `apps/element-alchemy/` 밖 파일에 의존하지 않는다.
- [ ] `game.js`에 DOM 접근이 없고, `innerHTML`을 쓰지 않는다.
- [ ] 브라우저 콘솔에 오류가 없다.
