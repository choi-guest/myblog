# 스타파이터 Review 결과

검토일: 2026-11-02 · 검토 대상: `apps/starfighter/` 전체(index.html, style.css, js/*.js, preview.svg)
검증 방법: 코드 전체 정독, Node로 로직 모듈 import 테스트·봇 시뮬레이션(스크래치 폴더), 내장 브라우저(localhost:8000) 확인.

## 1. 요약

**판정: 수정 필요**

게임 규칙·점수·10단계 수치·보안(innerHTML 미사용, 외부 의존 없음)·독창성 요건은 spec과 대부분 일치하고 콘솔 오류도 없다. 다만 다음 두 가지는 출시 전에 고쳐야 한다.

- **짧은 화면 레이아웃 (높음)**: 게임 열 폭의 하한값 `max(240px, …)` 때문에 375×600 같은 짧은 화면에서 단계 선택 버튼이 잘리고, 터치 모드에서는 [보조 무기] 버튼이 화면 밖으로 밀려난다.
- **오비탈 코어가 지나치게 김 (중간)**: 무적 봇으로도 우두머리전에만 파워 1이면 약 6~7분, 파워 3이면 약 1분 40초가 걸린다. 다른 단계는 1분 안팎이다.

이 밖에 aria-live 알림이 덮어써지는 문제(중간)와 낮음 등급 문제 몇 가지가 있다.

## 3. 발견한 문제

### #1 [높음] 짧은 화면에서 단계 버튼이 잘리고 터치용 보조 무기 버튼이 화면 밖으로 나감
- **위치**: style.css:239, style.css:244 (`max(240px, calc((100dvh - var(--chrome)) * 9 / 16))`), style.css:452 (`repeat(5, 56px)` 고정), style.css:124 (`--chrome: 248px`)
- **재현**:
  - 375×600에서 열면 game-col 폭이 240px로 고정된다. 단계 격자는 304px가 필요한데 쓸 수 있는 폭은 214px이다. 그래서 1·6단계 버튼 왼쪽과 5·10단계 버튼 오른쪽이 잘린다(1단계 버튼 x=36, 게임 영역 x=68). 가운데 정렬된 채 넘치는 부분이라 왼쪽은 스크롤로도 볼 수 없다.
  - 같은 화면을 터치 모드로 두면 #special-btn이 top 604 / bottom 660에 놓여 viewport(600) 밖으로 나간다. 실제 상단 높이(헤더 + HUD 3줄 = 169px)와 `--chrome` 추정값도 맞지 않는다.
  - 375×812 터치 모드에서도 열 폭 317px에서 안쪽 폭이 291px라 격자가 양쪽으로 약 6px씩 잘린다.
- **제안**:
  - 240px 하한을 없애거나 아주 작게 낮춘다.
  - 단계 격자를 `repeat(5, minmax(44px, 56px))` 또는 `repeat(5, 1fr)`로 바꾸고, 시작 화면은 게임 영역보다 넓게 쓰도록 한다(예: 오버레이를 stage-wrap 밖에 두기).
  - `--chrome`을 측정값으로 쓰거나 grid/flex 레이아웃(`grid-template-rows: auto 1fr auto` + 캔버스 `aspect-ratio`, `max-height`)으로 바꿔 조작 띠를 항상 화면 안에 둔다.

### #2 [중간] 오비탈 코어 우두머리전이 지나치게 김
- **위치**: config.js:192 (core hp 200), config.js:196 (exposeTime 8, exposedAmp 120, exposedFreq 1.6), boss.js:155, boss.js:215
- **재현**: Node 무적 봇(가장 낮은 약점을 따라 x 이동, 상시 발사, 게이지가 차면 보조 무기 사용)으로 측정했다.
  - 우두머리전 시간: 파워 1일 때 410~418초, 파워 3일 때 101~103초. 10단계 전체는 233~437초다(무기 3종 × 시드 3개). 다른 단계는 30~110초다.
  - 노출 8초 동안 깎이는 HP는 파워 1에서 6~9, 파워 3에서 22~25뿐이다. 대부분의 피해는 재생성이 끝난 뒤 "계속 노출" 구간에 들어간다. 이 구간에서 코어는 최고 약 192lp/s(플레이어 210lp/s)로 좌우 왕복해 맞히기 어렵다.
  - 10단계에 오면 피격으로 파워가 1~2인 경우가 많을 것이라 실제 체감은 3~6분 이상으로 예상된다.
- **제안**: 다음 중 하나 이상.
  - 코어 HP 200→120 수준
  - 노출 시간 8→12초
  - 노출 중 이동 폭이나 속도 축소(exposedAmp 120→80, exposedFreq 1.6→1.0)
  - 위성 HP 15→10
  - 목표: 파워 2 기준 약 90초

### #3 [중간] aria-live 알림이 같은 프레임 안에서 덮어써져 "보조 무기 준비 완료"가 사라짐
- **위치**: hud.js:195-203 (매번 비운 뒤 30ms 타이머로 마지막 문장 하나만 넣음), main.js:356-361, game.js:119·729·739
- **재현**: Node에서 에너지 95 상태로 에너지 결정을 먹으면 사건 순서가 `specialReady, item`이다. announce가 마지막 호출만 남기므로 "에너지 결정 획득, 에너지 100%"만 읽히고 "보조 무기 준비 완료"는 사라진다. 처치 → specialReady → 같은 스텝의 hit처럼 겹치는 경우도 마찬가지다.
- **제안**: 한 프레임의 문장을 모아 `. `로 이어 한 번에 넣거나 짧은 큐로 순차 출력한다. 우선순위(피격 > 보조 무기 준비 > 아이템)를 두는 방법도 있다.

### #4 [낮음] 일시정지 메뉴에서 단계 선택으로 나가면 최고 점수가 저장되지 않음
- **위치**: main.js:261 (showMenu), main.js:304-311
- **재현**: 진행 중 점수가 최고 점수보다 높을 때 [일시정지] → [단계 선택으로]를 누르면 저장되지 않는다(HUD에서만 max로 보임).
- **제안**: 단계 선택으로 나갈 때 `updateBest(game.getState().score)`를 호출한다.

### #5 [낮음] 9단계 웨이브 3 복합 대형(V자 축소판)과 쌍기둥 교차 시 적이 겹침
- **위치**: config.js:73 (`veeDx: 20, veeDy: 16`), formations.js:127-143, formations.js:176-185
- **재현**: Node로 60초 동안 자리 간 가장자리 거리를 계산했다.
  - ringVee: V자 이웃 자리 간격이 25.6lp인데 수호기 15 + 방패기 13, 분열기 14 + 수호기 15가 붙어 있어 **항상** 2.4~3.4lp 겹친다. 보호막 고리(+6)까지 그리면 더 뭉쳐 보인다.
  - pillars: 두 기둥이 자리를 바꾸는 1.5초 동안 서로 통과하면서 최대 12lp 겹친다(전체 시간의 약 6%).
- **제안**: ringVee의 veeDx를 24 이상, veeDy를 20 이상으로 늘린다. 대형 영역 y 300 안에 들어가는지는 다시 확인한다. 쌍기둥은 교차할 때 한 기둥의 x에 ±subGap 오프셋을 반대로 주거나, 교차 대신 위아래로 엇갈려 지나가게 한다.

### #6 [낮음] 라이트 모드에서 적 탄과 정찰기 색이 거의 같음
- **위치**: style.css:28 (`--enemy-scout: #b42318`), style.css:35 (`--enemy-shot: #c23a00`). 다크 style.css:76, 83도 살구색과 주황색으로 비슷함
- **근거**: 두 색의 명도 대비가 1.22(다크 1.20)이고 색상도 모두 빨강·주황 계열이다. 모양(원과 삼각형)과 테두리로 구분은 되지만, 이탈한 정찰기와 탄이 섞이면 한눈에 알아보기 어렵다.
- **제안**: 적 탄을 정찰기와 다른 색 계열(예: 라이트는 짙은 자홍이나 검정 테두리 + 노랑 코어, 다크는 노랑 계열)로 바꾸거나, 정찰기 색을 다른 계열로 옮긴다.

## 4. 확인하지 못한 항목과 이유

- **실시간 플레이 체감, 60fps, 단계 클리어 대화상자의 실제 화면**: 내장 브라우저 창이 숨겨진 상태여서 rAF가 초당 0~2회로 묶였고, 도중에 blur로 자동 일시정지되기도 했다. 이동·발사·처치·HUD 갱신·일시정지·게임 오버 대화상자(6단계 방치 → "게임 오버 / 6단계 · 웨이브 1", [다시 도전] 포커스)까지는 브라우저에서 확인했다. 단계 클리어 흐름(보너스·잠금 해제·이어 가기)은 Node와 코드로만 확인했다.
- **우두머리 화면(프리즘 반사판·광선, 오비탈 위성)의 시각 확인**: 같은 이유로 5·10단계 우두머리까지 진행하지 못했다. 로직은 Node로 확인했다.
- **prefers-reduced-motion 실제 화면**: 브라우저 도구에 해당 에뮬레이션이 없어 코드 검토로 대신했다.
- **소리 재생**: 출력은 들을 수 없어 코드만 확인했다(기본 꺼짐, 사용자 동작 후 생성).
- **실기기 터치(iOS Safari 주소창 변화, 당겨서 새로고침)**: 합성 PointerEvent로 끌기 이동만 확인했다.

정리: 브라우저 설정은 desktop 뷰포트 + light 색상으로 되돌렸고, 테스트 중 넣은 localStorage 값(`starfighter:*`)은 모두 지웠다.
