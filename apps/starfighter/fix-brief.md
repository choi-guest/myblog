# Build 수정 지침 (Review 1차 반영)

## 역할
`apps/starfighter/review.md`에서 지적된 문제를 수정한다.

## 수정 범위
- 고칠 수 있는 파일: `apps/starfighter/index.html`, `style.css`, `js/*.js`
- 그 밖의 파일(review.md, spec.md, 지침 파일들, 다른 앱, 블로그 파일, CLAUDE.md, .claude/)은 수정 금지. 커밋 금지. 서버를 띄우지 않는다.
- 임시 테스트 스크립트는 스크래치 폴더에만 둔다.

## 고칠 것
1. **[높음] 짧은 화면 레이아웃 깨짐** — 375×600, 375×667, 375×812(터치 모드 포함), 320×568에서:
   - 단계 선택 격자·보조 무기 버튼·HUD가 잘리거나 viewport 밖으로 나가지 않게 한다. 격자는 폭에 맞춰 줄어들거나 줄바꿈되게(고정 5×56px 대신 유동 폭, 버튼은 44×44px 이상 유지).
   - 게임 열 폭 `max(240px, …)` 고정 대신, 화면 높이·폭에 맞춰 게임 영역(360:640 비율)이 줄어들되 오버레이 내용은 스크롤로 모두 볼 수 있게 한다.
   - 가로 스크롤 없음 유지.
2. **[중간] 오비탈 코어가 너무 김** — 파워 1 기준 우두머리전이 약 90~150초, 파워 3 기준 약 45~90초가 되도록 HP·노출 시간·위성 재생성 주기 등을 조정한다. 10단계가 여전히 가장 어려운 우두머리전이 되게 한다. 프리즘(5단계)은 회피 봇 클리어율이 낮게 나왔으니, 무리하지 않은 선에서 10단계보다 쉽게 느껴지도록 점검한다(예: 광선 예고 시간, 탄 밀도). 조정한 값은 보고서에 적는다.
3. **[중간] aria-live 알림 덮어쓰기** — 한 스텝에 여러 사건이 있으면 중요한 알림("보조 무기 준비 완료", 우두머리 등장·격파, 피격, 단계 클리어)이 묻히지 않게 한다. 예: 한 프레임의 문장을 우선순위대로 합치거나 짧게 대기열로 처리.
4. **[낮음] 일시정지에서 [단계 선택으로] 나갈 때 최고 점수 저장** (`main.js`).
5. **[낮음] 9단계 웨이브 3 복합 대형 V자 겹침, 쌍기둥 자리 교체 시 겹침** — 적끼리 겹치지 않게 간격 조정.
6. **[낮음] 적 탄과 정찰기 색 구분** — 라이트/다크 모두 서로 다른 색 계열로 나누고, 배경 대비 3:1 이상 유지. 모양 차이도 유지.
7. **[낮음] 기타** — 게임 영역 포커스 테두리는 키보드 포커스 표시는 유지하되 플레이를 가리지 않게(예: 얇은 외곽선이나 출격 직후 잠시 표시), 메뉴 화면에서는 일시정지 버튼 비활성, 좁은 폭 HUD 줄바꿈 정리.

## 자체 점검
- `node --check`로 JS 13개 확인.
- 기존 시뮬레이션(스크래치 폴더의 sim.mjs, ev.mjs 등)을 다시 돌려 규칙·점수·10단계 표가 그대로인지(조정한 우두머리 수치 제외) 확인. 오비탈 코어·프리즘 소요 시간을 파워 1/3으로 다시 측정해 보고.
- 레이아웃은 CSS 계산으로 각 화면 크기에서 요소가 들어가는지 점검(브라우저 확인은 Review가 한다).
